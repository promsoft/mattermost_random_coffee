# Random Coffee Bot — архитектура

## Стек

- **Python 3.12+**, асинхронный рантайм (`asyncio`)
- **mattermostdriver** — REST API + WebSocket-клиент Mattermost
- **FastAPI + uvicorn** — HTTP-эндпоинт для callback'ов интерактивных кнопок
- **APScheduler** — cron-задачи (пн/ср/вс по Europe/Moscow)
- **SQLite + SQLAlchemy 2.x** (sync-движок достаточен для ≤50 участников) + **Alembic** для миграций
- **pydantic-settings** — конфиг из env / `.env`
- **Docker + docker compose** — деплой на хосте Mattermost
- **pytest** — тесты; **ruff** — линтер/форматтер

## Компоненты

```
┌─────────────────────────── bot (один процесс) ───────────────────────────┐
│                                                                           │
│  WebSocket listener ──┐                                                   │
│  (DM-сообщения,       │      ┌──────────────┐      ┌──────────────────┐   │
│   текстовые команды)  ├────▶ │ Command       │ ───▶ │ Domain services  │   │
│                       │      │ router        │      │  - Registration  │   │
│  HTTP server ─────────┘      └──────────────┘      │  - Matching      │   │
│  (POST /actions —                                  │  - MeetingFlow   │   │
│   кнопки interactive                               │  - Rating        │   │
│   message attachments)                             │  - Admin         │   │
│                                                    │  - Complaints    │   │
│  APScheduler ────────────────────────────────────▶ └────────┬─────────┘   │
│  (пн 07:00 пары, ср 14:00 статус, вс 14:00 оценки)          │             │
│                                                             ▼             │
│                                              SQLite (volume /data)        │
│                                                             │             │
│  Mattermost REST API ◀──────────────────────────────────────┘             │
│  (отправка DM, посты в канал анонсов)                                     │
└───────────────────────────────────────────────────────────────────────────┘
```

Один процесс, один контейнер. WebSocket — приём текстовых команд в DM; HTTP-сервер — приём
нажатий кнопок (Mattermost шлёт POST на URL интеграции; на Free Edition интерактивные кнопки
в message attachments работают, нужен только URL, достижимый с сервера Mattermost — на одном
хосте это адрес контейнера/хоста).

## Модель данных

```sql
users (
  id INTEGER PK,
  mm_user_id TEXT UNIQUE NOT NULL,      -- ID пользователя в Mattermost
  username TEXT NOT NULL,
  profile TEXT,                          -- свободный текст: telegram, whatsapp, о себе
  state TEXT NOT NULL,                   -- active | paused | paused_by_admin | paused_by_complaint
  unmatched_streak INTEGER DEFAULT 0,    -- сколько недель подряд без пары (приоритет матчинга)
  created_at, updated_at
)

meetings (
  id INTEGER PK,
  week_start DATE NOT NULL,              -- понедельник недели встречи
  user1_id, user2_id → users.id,
  status TEXT NOT NULL,
  -- scheduled        : пара собрана, уведомления отправлены
  -- declined         : один из участников отказался от этой пары (оба вернулись в пул)
  -- postpone_pending : один предложил перенос, ждём ответа второго
  -- postponed        : перенос принят → создаётся новая meeting на week_start+7
  -- cancelled        : отменена (вторым участником при переносе / админом / по статусу «отменили»)
  -- completed        : созвон состоялся (по итоговому опросу)
  -- no_response      : неделя кончилась, итог не получен
  midweek_status_u1 TEXT, midweek_status_u2 TEXT,  -- agreed | called | cancelled | no_contact
  rating_u1 INTEGER, rating_u2 INTEGER,            -- 0..5, оценка, поставленная этим участником
  postponed_from_id → meetings.id,       -- если встреча создана переносом
  cancelled_by TEXT,                     -- user | admin
  created_at, updated_at
)

complaints (
  id INTEGER PK,
  meeting_id → meetings.id,
  reporter_id, accused_id → users.id,
  text TEXT,
  status TEXT NOT NULL,                  -- open | resolved
  created_at, resolved_at
)
```

- **Рейтинг** не хранится отдельно: `rating(user) = SUM(оценок, полученных user)` по
  `completed`-встречам — считается запросом (≤50 участников, это копейки). Кэшировать не нужно.
- **Кулдаун пар**: пара (A, B) допустима, если нет meeting с этой парой (в любом порядке)
  с `week_start > today - 365 дней` — независимо от статуса (по спеке п. 9).

## Алгоритм матчинга (пн 07:00 МСК)

1. Берём всех `users.state = active`.
2. Сортируем: сначала по `unmatched_streak` (убыв.) — приоритет тем, кто остался без пары,
   затем по рейтингу (убыв.) — спека п. 8.
3. Жадно: берём первого без пары, ищем в остатке самого верхнего совместимого
   (не встречались за 365 дней). Нашли — пара; нет — кандидат уходит в пул свободных.
4. «Лишний» при нечётном числе остаётся в пуле свободных, `unmatched_streak += 1`;
   у получивших пару streak сбрасывается.
5. Пул свободных живёт всю неделю: отказ от пары (`declined`) и регистрация новых участников
   среди недели → попытка домэтчить из пула немедленно (тот же алгоритм по пулу).

## Жизненный цикл встречи

```
scheduled ──ср 14:00 опрос──▶ (статусы участников записываются)
   │
   ├─ участник «отказаться от пары» ──▶ declined ──▶ оба в пул свободных, домэтч
   ├─ участник «перенести» ──▶ postpone_pending ──▶ второй:
   │       ├─ принял  ──▶ postponed + новая meeting на след. неделю (пара та же)
   │       └─ отказал ──▶ cancelled (встреча несостоявшаяся)
   ├─ админ отменил ──▶ cancelled (cancelled_by = admin)
   └─ вс 14:00 итоговый опрос: «состоялась?» + оценка 0–5
           ├─ оба/один ответили «состоялась» ──▶ completed (+ оценки в рейтинг)
           ├─ «отменили / не созвонились»     ──▶ cancelled
           └─ никто не ответил                ──▶ no_response
```

Жалоба (`/пожаловаться` из карточки встречи) → `accused.state = paused_by_complaint`,
уведомление всем админам в DM; разблокировка — только командой админа.

## Интерфейс

### Участник (DM с ботом)

- Кнопки в приветствии/меню: **Зарегистрироваться · Пауза · Возобновить · Профиль · Помощь**
- Профиль: бот просит одним сообщением прислать контакты/о себе (свободный текст).
- Карточка пары (пн): кто пара, её профиль, кнопки **Отказаться от пары · Перенести · Пожаловаться**
- Опрос среды: кнопки **Договорились · Созвонились · Отменили · Ещё не связывались**
- Опрос воскресенья: **Состоялась / Не состоялась**, затем оценка **0–5** (кнопки)
- Текстовые fallback-команды: `помощь`, `регистрация`, `пауза`, `профиль` и т.д.

### Админ (DM, доступ по списку username'ов в конфиге)

- `админ встречи` — список встреч текущей недели со статусами
- `админ участники` — список участников с состоянием и рейтингом
- `админ отменить <meeting_id>`
- `админ пауза <username>` / `админ снять-паузу <username>` (в т.ч. разбор жалоб)

### Канал анонсов

- Пн после матчинга: «Неделя стартовала, собрано N пар, M в пуле. Хочешь участвовать — напиши боту»
- (пост-MVP) итоги недели/статистика

## Конфигурация (env)

`MM_URL`, `MM_BOT_TOKEN`, `ANNOUNCE_CHANNEL_ID`, `ADMIN_USERNAMES`, `TZ=Europe/Moscow`,
`MATCH_CRON`, `MIDWEEK_CRON`, `SURVEY_CRON`, `DB_PATH=/data/coffee.db`,
`ACTIONS_BASE_URL` (URL HTTP-эндпоинта кнопок, видимый серверу Mattermost).

## Надёжность

- Все рассылки идемпотентны: перед отправкой проверяем состояние в БД (рестарт контейнера
  посреди рассылки не дублирует сообщения и не теряет пары).
- При старте — догон пропущенных задач (если бот лежал в пн 07:00, матчинг выполнится при старте,
  если на этой неделе пар ещё нет).
- Ответы кнопок обрабатываются по `meeting_id` + `user_id` из контекста action'а — повторные
  нажатия безопасны.
